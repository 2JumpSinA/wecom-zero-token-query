# 10 · 泛化模型：从"品牌"到"维度 / 作用域"

> 上一版的"品牌"是写死在代码里的概念。这一版把它泛化成**维度（dimension）与作用域（scope）**：
> 品牌、渠道、区域、账号、门店组 —— 都只是同一套机制的实例。

## 1. 概念

| 概念 | 含义 | 例子 |
|---|---|---|
| **维度值**（scope value） | 一段输出可能"属于"的标签 | `品牌A隐形眼镜`、`品牌B隐形眼镜`、`美团`、`华东区` |
| **群的 scope** | 这个群只该看哪些标签的内容 | 品牌B群 → `["品牌B隐形眼镜"]` |
| **命令的 scopeByGroup** | 这条命令的输出要按群的 scope 裁剪 | 余额（一次查多个品牌）→ `true` |
| **无 scope** | 群没配 scope ⇒ **完全不裁剪**，看到全部 | 只服务自己的私人群 → `[]` |

裁剪规则（按**空行**切区块）：

1. 区块里出现了哪个已知 scope 值 → 归属该值
2. 沾到本群 scope 就保留；只沾别的就整块丢弃
3. 一个 scope 值都没出现的区块（标题、说明行）一律保留
4. 群 scope 为空 → 不裁剪
5. 裁完为空 → **退回原文**（绝不发空消息）
6. 单聊没有群身份 → 不裁剪

## 2. 配置写法（`commands.json`）

```json
{
  "groups": {
    "<品牌B群ID>": { "name": "品牌B数据播报", "scope": ["品牌B隐形眼镜"] },
    "<品牌A群ID>": { "name": "品牌A数据播报", "scope": ["品牌A隐形眼镜"] },
    "<我的群ID>": { "name": "我的查询群",  "scope": [] }
  },
  "commands": [
    {
      "id": "balance",
      "match": ["余额"],
      "chats": [],
      "scopeByGroup": true,          // ← 发送前按本群 scope 裁剪
      "cwd": "${HERE}\\scripts",
      "exe": "${PYTHON_EXE}",
      "args": ["-X", "utf8", "balance.py", "--preview"]
    }
  ]
}
```

**向后兼容**：老的 `"brands": [...]` 等价于 `"scope": [...]`；老的 `"brandScope": "group"` 等价于 `"scopeByGroup": true`。
两种写法可以共存，新配置建议统一用 `scope` / `scopeByGroup`。

## 3. 为什么值得泛化（三个真实场景）

| 场景 | 用 scope 怎么表达 |
|---|---|
| 多品牌集团，每个品牌一个群 | 群 scope = 品牌名；余额命令 `scopeByGroup: true` |
| 同一品牌，按**渠道**分群（美团群 / 饿了么群） | 群 scope = 渠道名；渠道报表按群裁剪 |
| 区域经理只看自己区域 | 群 scope = 区域名；一份全国报表按群裁剪 |

一句话：**只要你的输出里能"按标签分块"，就能用同一套机制做隔离**，不需要为每种隔离写代码。

## 4. 与人相关的两道闸（别混淆）

| 闸 | 控制什么 | 配置 |
|---|---|---|
| **谁能用** | 发送者身份 | `allowedUsers`（白名单）或 `allowAllUsers: true`（对所有人开放） |
| **在哪个群能用** | 会话范围 | `allowedChats`（群白名单）+ 每条命令的 `chats` |
| **能用哪条** | 命令粒度 | 每条命令的 `match` / `generic` / `chats` |

三者叠加后的效果（举例）：

- 私人群 + 只服务自己 → `allowedChats` 只有那个群，`allowedUsers` 只有你，命令 `chats` 全放
- 业务群 + 同事也能查 → 把同事 userid 加进 `allowedUsers`（或 `allowAllUsers: true`），
  但**命令表里不能有敏感项** —— 放行 = 他们能查你命令表里的全部数据

## 5. 变量展开（配合 `09`）

配置里所有路径字段都支持 `${变量}`：

| 变量 | 展开为 |
|---|---|
| `${HERE}` | 通道所在目录 |
| `${DSH_HOME}` | DSH 主目录 |
| `${USERPROFILE}` / `${TEMP}` / 任意环境变量 | 对应的值 |

这样"维度"和"路径"都不会把配置绑死在某台机器上。
