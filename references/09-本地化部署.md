# 09 · 本地化部署：从"我的机器"到"任何机器"

> 目标：把这个方案放到**别人的 Windows 机器**上，只改配置、不改代码、不改路径写死的任何东西。
> 一键入口：`scripts/install.ps1`；环境体检：`scripts/probe-env.ps1`。

## 1. 先探三件事（`probe-env.ps1` 会一次性告诉你）

| 探测项 | 为什么重要 | 不合格怎么办 |
|---|---|---|
| **Node ≥ 18** | 通道本体是 Node | 安装 Node（或让程序用绝对路径找） |
| **Python / 解释器** | 你的取数脚本靠它 | 装；或使用脚本自带的嵌入式运行时 |
| **网络可达性** | npm/pip 源、`wss://openws.work.weixin.qq.com` | 换镜像；企微长连接必须能出去 |
| **计划任务权限** | 常驻靠它 | 非管理员无法创建某些任务时，退化为"启动文件夹"方案 |
| **磁盘与内存** | 长期常驻 | 至少留几百 MB |

## 2. 目录约定（可移植的关键）

```
<安装目录>/                    例如 D:\wecom-fastlane   ← 任意路径，代码不关心
├── fastlane.mjs               通道本体
├── commands.json              ← 唯一需要按机器改的文件
├── secret.txt                 机器人 secret（不要外发）
├── logs\                      日志/心跳/PID（可随时删）
│   ├── fastlane.log           查询日志（谁问了什么、耗时）
│   └── collect.log            采集器日志（另有 history\ 的留档，见 11）
├── snapshots\                 采集结果的最新一份（配了 snapshot 才有，查询直接读它）
├── history\                   采集历史留档（每源每天一个 .jsonl，按 keepDays 自动清理）
└── scripts\、data\             你的取数脚本与原始数据（建议放这里，路径用 ${HERE} 引用）
```

**磁盘占用**（按 5 条源、10 分钟一轮、`keepDays: 14` 估算）：`snapshots\` 是常数（每源一个文件）；
`history\` 约 0.5–2 MB/天，14 天 ≈ 10–30 MB。日志按 5 MB 轮转（保留一个 `.1`）。
所以整套常驻的磁盘需求仍是"几百 MB"级别，`logs\`、`snapshots\`、`history\` 都可以随时删
（删了不影响可用性：查询会退回现场抓取，下一轮采集重建）。

**规则：配置里不要出现"我这台机器"的绝对路径。** 用变量：

| 变量 | 含义 |
|---|---|
| `${HERE}` | 通道所在目录（配置与脚本都在这儿时用它） |
| `${DSH_HOME}` | DSH 主目录（借用其模块/环境时用） |
| `${USERPROFILE}` / `${HOME}` / `${TEMP}` | 用户目录类 |
| 其它任意 `环境变量名` | 直接展开，例如 `${PYTHON_EXE}` |

例子：

```json
{
  "cwd": "${HERE}\\scripts",
  "exe": "${PYTHON_EXE}",
  "args": ["-X", "utf8", "shop_report.py", "--preview"]
}
```

这样换台机器只要设好 `PYTHON_EXE`，配置一个字都不用改。

## 3. 依赖与网络（国内环境特别注意）

| 依赖 | 安装 | 坑 |
|---|---|---|
| `@wecom/aibot-node-sdk` | `npm i @wecom/aibot-node-sdk` | 没独立 node_modules 时，程序会自动去 `$DSH_HOME/profiles/*/.dsh-module-fallback` 找 |
| 取数脚本的依赖 | `pip install -r requirements.txt` | **本机实测清华源对 pip 不可用**（报 `from versions: none`），阿里云/官方源正常 |
| GitHub 上的资源 | 走 `ghproxy.net` / `gh-proxy.com` / `ghfast.top` | `github.com` 与 `*.githubusercontent.com` 可能完全不通 |

**离线安装**：把通道目录 + 依赖（`node_modules`、Python 的 `site-packages` 或嵌入式运行时）一起打包带走，
目标机器不需要联网也能跑。

## 4. 凭据本地化

| 存法 | 适用 | 注意 |
|---|---|---|
| `secret.txt` | 单机单人 | **UTF-8 无 BOM、一行**；NTFS 权限限制为本人 |
| 环境变量（用户级） | 多进程共享 | `setx` 或注册表 `HKCU\Environment`；重登生效 |
| 系统凭据管理器 | 有多个凭据时 | 脚本用 `keyring` 读取 |
| **不要** | —— | 进 git、进聊天、写进 `commands.json`、截图 |

业务系统的登录态（token/cookie）同样按上表处理；并**为它准备一条健康检查命令**，见 `07 §3.1`。

## 5. 常驻（复用 `04` 的做法）

```cmd
schtasks /create /tn WecomFastlane /tr "wscript.exe //nologo <目录>\watchdog-hidden.vbs" /sc minute /mo 1 /f /rl LIMITED
```

要点只有两个：**动作必须是 wscript**（否则每分钟闪窗）、**心跳必须带 pid**（否则假健康）。
细节与原理见 `04-常驻与防闪窗.md`。

## 6. 升级与回滚

- 目录里放 `VERSION` 文件；升级 = 整目录替换（保留 `commands.json` / `secret.txt` / `logs`）
- **升级前先备份**：`<目录>\_backup\<版本>-<日期>\`
- 回滚 = 把备份目录换回来 + `schtasks /run` 重启，1 分钟内生效
- 有 git 的话直接 `git pull` 更省事；没有 git 就用 zip（本技能包就是 zip 分发的）

## 7. 换机器迁移清单

- [ ] 通道目录（含 `commands.json`、`secret.txt`）
- [ ] 取数脚本 + 它们的凭据/登录态
- [ ] 解释器：直接装，或把嵌入式运行时一起带
- [ ] 依赖：`node_modules` 与 Python 包
- [ ] `probe-env.ps1` 跑一遍，确认 Node/Python/网络都过
- [ ] `install.ps1` 注册任务 → `--check` → `--routes` → `--selftest` → 群里实测
- [ ] 旧机器上停掉（否则**两个进程连同一个机器人** → 消息可能被两边各回一次）

## 8. 可移植性自查表（贴到 README 里，谁接手都能查）

| 我这台机器特有的东西 | 通用化做法 |
|---|---|
| 绝对路径（`<你的脚本目录>\...`） | 改 `${HERE}` / 环境变量 |
| 特定 Python 解释器路径 | 配 `${PYTHON_EXE}`，或用 `probe-env` 自动探测 |
| 品牌名写进逻辑 | 改成"维度值"，见 `10` |
| 我的 userid / 群 ID | 文档里脱敏成占位符，配置里保留真实值 |
| 我的 webhook key / secret | 只留在本机文件，绝不进文档与仓库 |
| 只在某台机器装过的包 | 写进 `requirements.txt` / `package.json` |
