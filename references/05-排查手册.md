# 05 · 排查手册

**排查第一步永远是这三条**（在程序目录打开命令行）：

```cmd
type logs\fastlane.log        谁问了什么、命中了哪条、花了多久、输出多大
type logs\heartbeat.txt       死活：时间在 4 分钟内 = 连接健康
type logs\watchdog.log        自愈记录：健康时它是空的
```

## 完整排查表

| 症状 | 可能原因 | 怎么处理 |
|---|---|---|
| 群里 @ 完全没反应 | 机器人没加进群 | 群设置 → 添加机器人 |
| 同上 | `allowedUsers` 里没有这个人 | 从日志 `user=` 取值填进去，重启 |
| 同上 | 这个群不在 `allowedChats` | 把 `chat=` 的值补进去，重启 |
| 同上 | 程序没在跑 | 看 `logs\fastlane.pid` 的进程在不在；不在就 `schtasks /run /tn WecomFastlane` |
| 日志只有"收到消息"，没有"开始执行" | 触发词没命中 | `run-fastlane.cmd --routes` 核对写法；确认与 `match` 完全一致 |
| 回"这里能查多个品牌，请写明要哪个" | 单聊里用了通用词 | 说全名（如 `品牌B门店`）—— 这是设计行为，不是 bug |
| 回帮助、命令没执行 | 该命令没绑这个群（`chats`） | 在 `chats` 里加上该群 ID，重启 |
| 回复要等十几二十秒 | 脚本真的在取数 | 正常；占位消息会先到 |
| 正文里有 `<font color="comment">` | 脚本用了 HTML 颜色标签 | 让脚本改用 `**加粗**`；通道也会自动剥 |
| 中文乱码 / 方框 | 解释器没按 UTF-8 输出 | `args` 里加 `-X utf8`；确认脚本以 UTF-8 保存 |
| 屏幕每分钟闪一下黑窗 | 计划任务动作是 powershell | 改成 `wscript.exe //nologo …\watchdog-hidden.vbs` |
| 任务结果 `2147946720` | "已有实例在运行"（正常跳动） | 心跳新鲜就不用管 |
| 日志说"已有实例在运行，本进程退出" | 单实例保护生效 | 正常；确实要换配置就按 04 文档重启 |
| 查一半被告知"上一条查询还在执行" | 单飞锁（防两个抓取任务打架） | 等它出结果再发 |
| 说 `secret 缺失` | `secret.txt` 位置不对 / 带 BOM / 多行 | UTF-8 无 BOM 重存，确认只一行 |
| 说"找不到 @wecom/aibot-node-sdk" | 没装依赖 | 目录里 `npm i @wecom/aibot-node-sdk`，或设 `WECOM_FASTLANE_SDK` 指向它的 `dist/index.esm.js` |
| 认证失败 / 连不上 | secret 错、机器人被删、网络不通 | 核对 secret；确认能访问 `wss://openws.work.weixin.qq.com` |
| 重启电脑后不工作 | 计划任务"仅登录时运行" | 重新登录即可（开机不登录不会跑） |
| 提示端口/进程冲突 | 有两个实例 | 只留计划任务那个，关掉手动启动的窗口 |
| 群里出现**两条**回复 | 复用同一个机器人挂了 agent + 本通道 | 必须**另建一个机器人**给本通道 |
| 回复要等十几二十秒 | 这条命令没配 `snapshot`，还在现场抓取 | 加上 `"snapshot": "<源名>"` + 配好 `collect`，重启（见 `11`） |
| 正文首行有「⚠️ 数据已 N 分钟未更新」 | 采集器没采到新数据（或常驻进程刚起还没首采） | 看 `logs\collect.log`；`run-fastlane.cmd --collect <源>` 手动采一次，看它报什么错 |
| 收到「采集器数据陈旧」告警 | 某源采集连续失败，或常驻进程停了很久 | 先读 `logs\collect.log` 的失败原因；凭据类问题群里发「登录态」确认 |
| `snapshots\` 目录是空的 | 从来没采过（首采在启动约 30 秒后） | `run-fastlane.cmd --collect` 手动采一轮 |
| 改了脚本文案，群里回复还是旧的 | 查询读的是**采集结果**，不是现场 | 手动 `--collect <源>` 重采一次（或等下一轮） |
| 某源一直"从未采集成功" | 脚本在采集时也失败（路径/解释器/凭据） | `--collect <源>` 单跑这一条，按它的报错排查；快照为空时查询会自动回退现场抓取，所以不影响可用性 |

## 采集证据求助（照这个发，最省事）

1. `logs\fastlane.log` 最后 30 行
2. `logs\heartbeat.txt` 全文
3. `run-fastlane.cmd --check` 的输出（**不含 secret，可安全外发**）
4. 出了什么现象：**哪个群、什么时间、@ 了什么、期望看到什么、实际看到什么**（原文/截图最好）

> 报症状，不要先猜原因。"品牌B群里回了品牌A数据"这种描述，比"好像有点问题"有用一百倍。

## 调试用命令

```cmd
run-fastlane.cmd --check            配置/SDK/凭据/群绑定/安全护栏，不联网
run-fastlane.cmd --status           进程/连接/心跳/当前任务/最近执行（群里发「状态」同一份）
run-fastlane.cmd --routes           每个群 × 每个触发词解析成哪条命令，不联网
run-fastlane.cmd --as-group <群ID>  以某个群的视角试跑（应用该群作用域裁剪，但不发群）
run-fastlane.cmd --probe <脚本>     把任意脚本变成命令配置；加 --run 校验契约
run-fastlane.cmd --selftest         本地把每条命令跑一遍（不发群）
run-fastlane.cmd --selftest 余额     只跑一条
run-fastlane.cmd --alert-selftest   验证"连续失败告警"状态机（不联网、不发群）
run-fastlane.cmd --hint-selftest    验证"失败人话提示"规则命中情况（不联网、不发群）
run-fastlane.cmd --collect [源]     手动采一轮（联网取数、不发群），落 snapshots\ 与 history\
run-fastlane.cmd --query <命令>     离线预演群内渲染：读缓存 → 作用域裁剪 → 加数据时间（不发群）
run-fastlane.cmd --stale-selftest   验证"采集陈旧告警"判定（喂样本、不联网、不发群）
run-fastlane.cmd --history [源]     回看某天每轮采到了什么、有没有空档（加 --date YYYY-MM-DD）
run-fastlane.cmd --list             列出命令表
run-fastlane.cmd                   前台启动（排错用，Ctrl+C 退出）
```

> **群里发「状态」没反应？** 它是内建命令（`"builtin": "status"`）：确认还在 `commands.json` 里、
> 且 `chats` 允许当前群。这类命令不需要 `exe`/`args`。

> **新加的群不响应？** 光把群 ID 加进 `allowedChats` 还不够 —— 每条命令还有自己的 `chats` 白名单，
> 没列进去的命令在那个群会被当"未知命令"回帮助。加群时两处都要改，然后 `--routes` 核对。
