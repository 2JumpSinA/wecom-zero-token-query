# 08 · 脚本接入契约与探针

> 这一层是**整个方案的通用化关键**：通道不关心你的数据从哪来、用什么语言写，
> 只要求脚本满足下面四条。满足四条 = 能接进群。

## 1. 四条契约

### 契约 1 · 只读或可预演
提供 `--preview`（或 `--dry`、或"不带 `--send`"）开关，带上它时：

- 只把结果打印到 stdout
- **不发送任何消息**
- **不写任何状态**（"今天已推""已提醒过"这类）
- 失败时也不借机发告警

> 为什么反复强调"不写状态"：有的脚本用 `.shop_report_date` 记录"今天推过"，
> 一次手动查询就会把当天 09:00 的定时播报顶掉 —— 这是**静默故障**，最贵。

### 契约 2 · 正文可提取
把要发出去的那段夹在两条 `====`（≥10 个等号）之间；其余进度日志留在分隔线外。

```
=== 1) 拉取数据 ===          ← 噪声，通道会丢掉
========================================
### 门店营业情况播报
> 项目：某某品牌
> 统计时段：今日 00:00 起，截至 12:39
========================================
[done] 退出码 0              ← 噪声
```

也可以让通道抓整段 stdout（命令配置里 `extract: "stdout"`），但那样噪声也会进群。

### 契约 3 · 退出码有语义
- `0` = 成功
- 非 `0` = 失败，并把"人话原因"写到 stdout/stderr（通道会把退出码 + 最后几行贴回群）

### 契约 4 · 无交互、有超时
不能在运行时等待输入（群里没人能按回车）；单次运行要有上限，
配置里 `timeoutMs` 是通道侧兜底，脚本自己也该有请求超时。

## 2. 语言无关：三份最小实现

**Python**
```python
import sys
PREVIEW = "--preview" in sys.argv
def emit(md):                      # 契约 2：正文夹在分隔线之间
    print(); print("=" * 40); print(md); print("=" * 40)
def main():
    data = fetch()                 # 你的取数逻辑（契约 1：preview 时绝不下发）
    md = render(data)
    emit(md)
    if not PREVIEW: push(md)       # 只有真正运行时才推
    return 0
if __name__ == "__main__":
    try: sys.exit(main())
    except Exception as e:
        print(f"[失败] {type(e).__name__}: {e}"); sys.exit(1)   # 契约 3
```

**PowerShell**
```powershell
param([switch]$Preview)
$md = Get-Data | Format-Report
Write-Output ""; Write-Output ("=" * 40); Write-Output $md; Write-Output ("=" * 40)
if (-not $Preview) { Send-ToWeCom $md }
exit 0
```

**Node**
```js
const preview = process.argv.includes('--preview');
const md = render(await fetchData());
process.stdout.write(`\n${'='.repeat(40)}\n${md}\n${'='.repeat(40)}\n`);
if (!preview) await push(md);
```

## 3. 探针：把任意脚本变成一条命令配置

通道自带 `--probe`，用来回答"这个脚本能不能接、怎么接"：

```cmd
:: 静态分析：猜解释器、生成可直接粘贴的配置条目、列出要人工确认的点
run-fastlane.cmd --probe D:\scripts\report.py

:: 真跑一次做校验（会执行脚本！默认不跑，必须显式加 --run）
run-fastlane.cmd --probe D:\scripts\report.py --run --preview-flag --preview
```

`--run` 会检查四条契约并直接给结论：

| 检查 | 通过标准 |
|---|---|
| 退出码 | 0 |
| 正文提取 | 能取到非空正文（分隔线之间的内容） |
| 标签残留 | 正文里没有 `<font …>` 之类的标签 |
| 耗时 | 记录实测耗时，据此建议 `timeoutMs` |

**使用顺序**：`--probe`（静态）→ 按提示补全 → `--probe --run`（校验）→ 把生成的条目粘进 `commands.json`
→ `run-fastlane.cmd --selftest <触发词>` → `--routes` 核对分群 → 群里实测一条。

## 4. 常见的契约违规（都真实遇到过）

| 违规 | 后果 | 修法 |
|---|---|---|
| 脚本内部自己推群 | 群里同一份数据出现两次，分不清来源 | 加 preview 开关，把发送交给通道 |
| preview 模式下仍写"今天已推" | 手动查询顶掉当天定时播报（静默故障） | 状态写入加 `if not PREVIEW` 守卫 |
| preview 模式下仍发失败告警 | 占用了"6 小时只提醒一次"的额度，真故障被压掉 | 失败路径也尊重 preview |
| 输出用了 `<font color="...">` | 智能机器人不认 → 群里出现裸标签 | 改用 `**加粗**`；通道也会兜底剥 |
| 运行时等待输入 | 进程挂住直到超时，群消息永远不回 | 去掉交互，或加"非交互模式" |
| 中文乱码 | 群里出现方块/乱码 | 解释器加 `-X utf8`，文件存 UTF-8 |
| 取数失败却返回 0 | 群里显示"0 家门店"，被当成正常 | 失败必须非 0 退出 + 明确原因 |

## 5. 回归测试（强烈建议）

对"preview 绝不偷推"这条，写一个可重复执行的断言，别靠人眼检查：

```python
# _preview_check.py 思路：把 requests.post 换成会抛异常的哨兵
requests.post = lambda *a, **k: (_ for _ in ()).throw(AssertionError("preview 竟然发了请求"))
bot.PREVIEW = True
bot.send_to_wecom("DUMMY", "### 测试")      # 应该只打印、不抛异常
```
