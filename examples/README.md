# 三个样板适配器：把「取数层」的三种典型路径变成可跑代码

这三个文件对应 `references/07-取数路径.md` 里的三条主线。**它们都能离线跑**（`--demo`），
所以你可以先把整条链路打通，再去填凭据和接口细节。

| 文件 | 对应平台类型 | 核心难点 | 内置了哪些"实战模式" |
|---|---|---|---|
| `adapter-api.py` | **A 有正式 API** | 签名/换 token、限流、分页 | HMAC 签名、access_token 缓存、429 退避、业务码→人话 |
| `adapter-private-api.py` | **B 私有接口（中台/后台 XHR）** | 登录态复用、参数加密、失效识别 | **token 注入优先于账号登录**、AES-CBC 参数加解密、`重新登陆/401` 失效判定、重试退避 |
| `adapter-export-file.py` | **C 只有导出文件** | 数据脏、列名会变、编码 | 列名映射（不用列号）、GBK/UTF-8 自适应、**已知非异常台账剔除**、缺列显式报错 |

> B 号样板的模式来自一个真实投产项目（中台订单拉取），**已全面脱敏**：
> 域名、密钥、字段名、品牌名、路径全部替换为占位符。留下的只有可复用的结构：
> 登录态怎么拿、失效怎么认、失败怎么退避、字段怎么归一。

## 一句话用法

```cmd
:: 1) 先离线打通链路（不联网、不需凭据）
python adapter-private-api.py --demo

:: 2) 用通道探针验证它满足契约，并生成配置条目
run-fastlane.cmd --probe examples\adapter-private-api.py --run --exe <python.exe> --preview-flag --demo

:: 3) 填 4~5 处 TODO（见每个文件里的标注），去掉 --demo 再跑一次
python adapter-private-api.py --preview

:: 4) 把探针给出的 JSON 条目粘进 commands.json，然后
run-fastlane.cmd --selftest <触发词>
run-fastlane.cmd --routes
```

## 每个文件里要改的地方（都标了 `TODO n/5`）

| 1 | 站点常量：`API_BASE` / 超时 / 重试次数 | 抓包或文档里拿；**不要写进代码仓库**，用环境变量 |
| 2 | 凭据与签名 | 优先"复用 token"而不是"账号密码登录"——后者会把网页端挤下线 |
| 3 | 接口路径与字段归一化 | 把平台字段收敛成你自己的一套名字；换平台时只改这一处 |

## 三条通用经验（都来自真实踩坑）

1. **登录态失效必须显式报错，绝不能静默返回 0 条。**
   群里看到"今天 0 家门店"和看到"登录态已失效，请重新登录"，后者的价值高一个数量级。
   样板 B 里的 `AUTH_ERROR_MARKERS` + `is_auth_error()` 就是干这个的。
2. **状态写入要能预演。**
   如果你的脚本会记录"今天已推过"，务必让它尊重预演开关 —— 否则一次手动查询会顶掉当天的定时播报。
3. **先落盘原始数据，再渲染。**
   文案和口径会反复改；只存渲染结果的话，每次都要重新取数。

## 登录态续期（这类系统最大的运维痛点）

真实经验：**多数国内中台不发 refresh_token，token 就是会过期**。所以样板 B 给了三件套：

| 手段 | 命令 | 什么时候用 |
|---|---|---|
| 查一下还有效吗 | `python adapter-private-api.py --check-auth` | 定期/怀疑失效时；比"等查询失败才发现"好 |
| 注入新 token | `python adapter-private-api.py --set-token <从浏览器复制的 token>` | token 过期时，10 秒搞定，不用改代码 |
| 自动续期（若有） | 实现 `refresh_session()` 里的 TODO | 平台**确实**提供 refresh_token 时 |

配套的三条纪律：

1. **失效要显式报错**，绝不能静默返回 0 条 —— 群里看到"0 家门店"比看到报错危险得多；
2. **缓存 token 优先于账号密码登录** —— 后者会把用户正在用的网页端挤下线；
3. 把 `--check-auth` 挂成一条群命令（例如「登录态」），谁都能随时问一句。

## 与通道的关系

适配器**只负责取数 + 打印**，通道负责"收消息 / 匹配命令 / 回群"。
所以适配器里**不要**出现任何企微推送代码 —— 那会让同一份数据在群里出现两次。
