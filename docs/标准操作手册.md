## 1. 这套东西是什么（3 分钟看懂）

**一句话**：让企业微信里的一个机器人，收到固定命令后**直接在你电脑上跑脚本**，把结果发回群里 —— 全程**不经过 AI 模型，不消耗 token**。

**完整的一条数据要走过三段路**：

| 段 | 做什么 | 谁来做 |
|---|---|---|
| **1 取数** | 从平台后台把数字读出来 | 你的数据脚本（agent 帮你写） |
| **2 成文** | 把原始数字变成一条能发的播报 | 同一个脚本 |
| **3 投递** | 群里 @ 一下，脚本跑起来，结果回到群里 | 本手册要部署的「快通道」程序 |

```
你在群里 @数据查询 余额
        │
        ▼
   企微服务器  ──(本机主动连出去的长连接)──►  你电脑上的小程序
                                                │
                                                ├─ 看命令表：命中"余额"
                                                ├─ 先回一句"正在取数…"
                                                ├─ 跑你电脑上的 Python 脚本
                                                │      （脚本自己去平台后台取数）
                                                └─ 把脚本打印的结果发回群里
```

**为什么要这么做**：如果让 AI 助手（agent）去跑脚本，每收一条消息都要把整段聊天记录重新"读"一遍给模型听，这是要花钱的。而"查余额""看今天订单"这类查询每天要问很多遍、问法还都一样 —— 这种重复劳动交给脚本就好，不必花钱请模型代劳。

**你需要知道的两个关键事实**：

1. 脚本**不可能**跑在企微服务器上。企微只提供"壳"，代码必须跑在你自己电脑上 —— 所以你的电脑要开着机、并且处于登录状态。
2. 这台机器人**只能读、不能写**。它只会执行你在配置表里写死的那几条查询命令，别人 @ 它也只能拿到那几类数据。

## 2. 数据是怎么来的：三条取数路线

这一章解释"脚本到底从哪儿把数字拿出来的"。**你不需要会写，但需要看懂，因为要由你决定走哪条路。**

### 2.1 先说清楚一件事

数据不在天上，它就在**平台自己的商家后台**里 —— 就是平时用浏览器登录、点开能看到的那些页面。
脚本做的事情，本质上是**替你登录后台、把数字读出来、排成一条消息**。

所以真正的问题从来不是"怎么算"，而是这两个：

- **怎么登录**（第 3 章专门讲）
- **走哪条路把数字读出来**（本章）

### 2.2 三条路线

| 路线 | 适用情况 | 优点 | 代价 |
|---|---|---|---|
| **一、自有中台接口** | 公司自己的中台已经把各平台数据汇总好了 | **最省事、最稳**。一次登录拿令牌，之后按接口翻页取数 | 属于单点登录：重新登录会把网页端挤下线 |
| **二、平台 H5 接口 + Cookie** | 平台有能直接调的接口，签名用 Cookie 里的令牌算 | 纯网络请求就能跑，**不用开浏览器**，轻快 | 签名算法可能随平台改；令牌有换发时刻，那一轮会失败 |
| **三、浏览器自动化** | 接口被网关拦死，签名只在页面脚本里生成 | **没有它就拿不到数据**时的唯一办法 | 重、慢、对环境敏感，偶尔需要调启动参数 |

### 2.3 怎么选：一条铁律

> **先问"有没有能直接调的接口"，再考虑"爬页面"。**

顺序是：

1. **先看自有中台** —— 如果中台已经有这个数，直接走中台。这是最省事的一条，**很多需求到这一步就结束了**。
2. 中台没有，再看**平台有没有 H5 接口**，能不能用 Cookie 里的令牌签名。能，就走路线二。
3. 接口被网关挡死、签名只在页面里现算，才动用**浏览器自动化**（路线三）。

**一个反直觉但很重要的经验**：中台往往就是各平台数据的汇总方。
与其去逆向每个平台的接口，不如先问一句"中台是不是已经有这个数了" —— 我们这套系统最后就是靠这个判断省掉了大量工作。

> 这三条路线怎么选，**不需要你自己判断**。把需求讲给 agent，让它先去"勘察"平台，
> 它会告诉你走哪条路、为什么。你只需要在它给出结论时确认一下（比如"会不会把我挤下线"）。

## 3. 登录态：无人值守的第一道坎

**这一章是整份手册里最值钱的部分。**
脚本能不能"自己跑"，99% 取决于它能不能"一直保持登录"。取数逻辑反而是简单的。

### 3.1 什么是"登录态"

你在浏览器里登录了平台后台，关掉页面再打开，发现还是登录状态 —— 因为浏览器替你保存了一份凭据（通常是 Cookie）。
脚本要自动取数，就得**也拿到这么一份凭据**，并且**让它一直是有效的**。

### 3.2 凭据可以放在哪里

| 放法 | 说明 |
|---|---|
| 浏览器用户目录 | 让脚本用一个独立的浏览器目录，你在里面登录一次，它就一直用这个身份 |
| Cookie 文件 | 把登录后的 Cookie 存成一个文件，脚本每次读它 |
| 系统凭据管理器 | Windows 自带的加密存储，最安全；凭据太长还要**分片存**（单条有长度上限） |

### 3.3 为什么它会失效

- **平台会定期换发令牌** —— 到点就换，那一瞬间的请求会失败（但通常能自动续上）
- **你主动退出登录** —— 立刻失效
- **单点登录会互相挤** —— 有些系统里重新登录一次，会把别处已经登录的挤下线

### 3.4 怎么做到"无人值守"

这是衡量一套脚本好不好的唯一标准：

> **它能不能连续一周不用人去点它？**

具体做法：

1. **能自动续期的就自动续。** 大多数平台换发令牌时会把新的令牌放在响应里，脚本读到就写回文件，下次接着用 —— 你完全无感。
2. **不能自动续的，把"失效"和"网络抖动"分开报。** 这两件事的处理方式完全不同：一个要人立刻去重新登录，一个等二十秒就好。混在一起报，人会先白跑一趟重新登录，几次之后就再也不信这条告警了。
3. **临时失败要自动重试。** 早上第一次取数常因页面没准备好而失败，重试两三次通常就过了。

### 3.5 一条铁律

> **凭据只留本机。**

- 不要写进配置文件（配置可能会被拷给别人）
- 不要发到聊天里、不要截图
- 不要出现在播报正文里

我们的做法里还有一道兜底：**播报正文如果出现 8 位以上连续数字，直接拦下不发送** —— 防止平台的响应里夹带了手机号之类的信息被误发到群里。

## 4. 脚本是怎么开发的：把需求说清楚就够了

**你不需要会写代码。你需要会"说清楚"。**

这一章教你两件事：怎么把需求说明白，怎么验收。

### 4.1 一个真实的需求原话

整套系统是从这样一句话开始的：

> 「每小时自动播报订单取消占比，且不把个人账号密码、客户信息暴露给任何第三方。」

注意它包含三件事：**多久跑一次**、**要什么数**、**什么不许发出去**。这三件事说清楚，剩下的交给 agent。

### 4.2 开发四步

| 步骤 | 做什么 | 你要做的 |
|---|---|---|
| **1 说清要什么** | 多久跑一次、要什么数、什么不许发出去 | 打字 |
| **2 先勘察，再动手** | agent 去摸清：有没有现成接口、登录怎么保持、数据长什么样 | 确认它的结论 |
| **3 固化成脚本** | 把一次能跑通的命令，变成能重复跑、失败会明确报错的脚本 | 验收 |
| **4 加定时与推送** | 挂到计划任务定时跑；结果推企微 | 按第 8、12 章做 |

**最关键的是第 2 步**。不要一上来就让 agent 写代码，先让它去"勘察"。勘察结论会告诉你：走第 2 章的哪条路线、登录态怎么处理、有没有暗坑。

### 4.3 直接复制这段话术

把下面这段**原样发给你的 AI 助手 / agent**（DSH 或你用的其它工具），把方括号里的内容改成你要查的东西：

```
请帮我做一个数据播报脚本，需求如下：

【要什么】每小时查一次【平台A 后台里我名下门店的订单取消占比】。
【怎么发】结果推送到企业微信，接收方是【群机器人 webhook】。
【红线】不把个人账号密码、客户信息暴露给任何第三方。

请严格按这个顺序做，每一步先给我结论再继续：
1. 先勘察：这个数据应该从哪来？自有中台有没有现成的？如果没有，
   平台有没有能直接调的接口？还是必须用浏览器自动化？把三条路线
   的可行性分别告诉我，并推荐一条。
2. 告诉我登录态怎么处理：凭据放在哪、会不会失效、失效了我需要做什么。
3. 再开始写脚本。

脚本必须满足这几条约定（我要把它接到企业微信查询通道上）：
1. 只打印结果，绝不发送任何消息、绝不上传任何数据；打印的正文要夹在
   两条"======"分隔线之间（比如 40 个等号一行，正文一行，再来 40 个等号）。
2. 正文用企业微信 markdown 语法：标题用 ###，说明行用 > 开头，强调用 **加粗**。
   不要使用 <font color="..."> 这类 HTML 颜色标签。
3. 成功时退出码为 0，失败时把错误信息打到屏幕上并返回非 0 退出码。
4. 区分"凭据失效"和"网络抖动"这两类错误，后者要能自动重试。
5. 再加一个 --preview 参数：带上它时只打印、不做任何写操作、不发送。

最后告诉我：脚本要用哪个 Python 解释器跑、完整命令怎么写。
```

### 4.4 怎么验收（三条，缺一不可）

1. **能跑通** —— 在命令行里手工跑一次，屏幕上能看到数据。
2. **只打印、不乱发** —— 加上 `--preview` 跑，**群里不应该出现任何消息**。
3. **失败会报错** —— 故意断网或改错密码跑一次，它应该明确报错，而不是安静地输出一堆 0。

> **为什么第 2 条这么重要**：快通道需要把脚本打印的文字原样搬回群里。
> 如果脚本自己也往群里推一条，群里就会同一条数据出现两次 —— 而且你分不清哪条是谁发的。

**记住三样东西，第 9 步要用**：

| 记什么 | 例子 |
|---|---|
| 脚本的完整路径 | `D:\我的脚本\shops\daily_run.py` |
| 用哪个 Python 跑 | `D:\我的脚本\runtime\python\python.exe` |
| 完整命令怎么写 | `python.exe shops\daily_run.py --dry` |

## 5. 开工前你要准备什么

| 需要什么 | 说明 | 没有怎么办 |
|---|---|---|
| 一台 Windows 电脑 | 建议一直开着（脚本跑在它上面） | —— |
| 企业微信的**管理员权限** | 要进管理后台建机器人 | 找公司企微管理员帮你建，把 botId 和 secret 给你 |
| Node.js（18 以上） | 那个小程序要靠它跑 | 让 agent 帮你装，或问同事要安装包 |
| 一个能查数据的 Python 脚本 | 例如"查余额""查订单" | **交给 agent 生成**，见第 8 步 |
| 大约 30 分钟 | 第一次会慢一点，之后加新命令只要 3 分钟 | —— |

> **先确认 Node 装没装**：按 `Win + R`，输入 `cmd` 回车，在黑窗口里输入 `node -v` 回车。
> 如果显示 `v18.x` 或更高（比如 `v24.21.0`）就是装好了；如果提示"不是内部或外部命令"，说明没装。

## 6. 第一步：在企微后台建一个「智能机器人」

1. 用管理员账号登录企业微信管理后台（浏览器打开 `work.weixin.qq.com`，扫码登录）。
2. 在后台找到 **「智能机器人」**（通常在"应用管理"或"协作"分类下；不同版本菜单名略有差异，认准**"智能机器人"**这个词）。
3. 点 **新建 / 创建机器人**，给它起个一眼能懂的名字，例如 **`数据查询`**。
4. **关键**：接收消息的方式一定要选 **「长连接」/「WebSocket 长连接」**。
   - 选这个的原因：机器人由你的电脑**主动连出去**，所以你**不需要**公网 IP、不需要域名、不需要配回调地址。
   - 如果它只让你填"回调 URL / 接收消息服务器配置"，说明你进错了地方（那是"自建应用"），回到上一步找"智能机器人"。
5. 建好后，页面上会出现两串东西，**都记下来**：
   - **botId**：形如 `aibXXXXXXX-XXXXXXXXXXXX_XXXXXXXX`（**不是秘密**，可以随便贴给我们）
   - **secret**：一长串随机字符（**是密码**，不要发到微信/群里，只写进自己电脑的文件）
6. 把这个机器人**添加到你要用的群里**（在群设置里"添加群机器人"，或在机器人页面里选"添加到群"）。不加进群，@ 它就没反应。

> ⚠️ **不要复用现有的 AI 助手机器人**。要另建一个。原因：同一个机器人如果被两个程序同时连着，群里 @ 一次会被两边各回一条，而且 AI 助手照样会处理一遍（照样花钱）。分开建，各管各的。

## 7. 第二步：把程序目录放到你的电脑上

这里假设你把它放在 `D:\我的程序\wecom-fastlane\`（**你可以换成别的路径，但整份手册里的路径要一起换**）。

需要的文件（找同事要，或从已有的电脑上整个文件夹复制）：

```
wecom-fastlane\
├── fastlane.mjs            主程序（不用改）
├── commands.json           配置文件（你要改的就是它）
├── secret.txt              机器人密码（一行）
├── run-fastlane.cmd        启动器
├── start-hidden.vbs        静默启动
├── fastlane-watchdog.ps1   看门狗（掉线自动拉起）
├── watchdog-hidden.vbs     让看门狗不闪窗
├── _preview_check.py       回归自检（可选）
└── logs\                   日志目录（自动生成，不用管）
```

> **别用记事本存 `secret.txt`**：用记事本另存为时可能带一个隐藏的"BOM"标记，会让密码校验失败。
> 推荐用 **Notepad++** 或 **VS Code** 保存为 **UTF-8（无 BOM）**，并且**只有一行、结尾不要多空行**。

## 8. 第三步：让 agent 帮你写出数据脚本

这一步不用你写代码。**用第 4.3 节那段话术**，把方括号里的内容改成你要查的东西，发给 agent。

### 8.1 拿到脚本后，你要做三件事

1. **让它先跑通一次。** 在命令行里手工跑，确认能打印出结果。
2. **确认"只打印、不发送"。** 加上 `--preview`（或 `--dry`、或不带 `--send`，看脚本用哪个）再跑一次，**群里必须没有任何动静**。
3. **问清楚登录态怎么办。** 直接问 agent：

   ```
   这个脚本的登录凭据放在哪？多久会失效一次？失效了我需要做什么？
   能不能自动续期？如果续不了，它报错时会不会明确告诉我是"需要重新登录"，
   而不是让我以为是网络问题？
   ```

### 8.2 凭据失效了怎么办

- **能自动续期的**（大多数情况）：你什么都不用做。
- **不能自动续期的**：agent 通常会给你一个"重新登录"的小工具（可能叫 `login.bat` 之类）。失效时双击它，按提示扫码登录一次即可。
  **注意：通常只需要重新登录那一个账号**，其他账号不受影响。

> 判断标准还是那句话：**它能不能连续一周不用人去点它？** 能，就算过关。

## 9. 第四步：填配置文件 commands.json

用 Notepad++ / VS Code 打开 `commands.json`，**只改下面这几处**：

### 9.1 botId

```json
"botId": "把第 6 步拿到的 botId 粘进来",
```

### 9.2 谁能用（访问控制）

```json
"allowedUsers": ["把允许使用的人的 userid 粘进来"],
```

**userid 怎么拿**：先随便填一个占位（比如 `"unknown"`），让这个人去群里 @ 一次机器人，
然后打开 `logs\fastlane.log`，会看到这样一行：

```
[2026-09-19 12:36:01] 收到消息 chattype=group chat=<群ID>(品牌A数据播报) user=<userid> text="订单"
```

- `user=` 后面那串就是 **userid**（填进 `allowedUsers`）
- `chat=` 后面那串就是 **群 ID**（填进下面的 `allowedChats` 和 `groups`）

**谁能用这台机器人**，有三种写法（**改完要重启才生效**，见 14.3）：

| 写法 | 效果 |
|---|---|
| `"allowedUsers": ["userid1", "userid2"]` | 只给名单里的人用；不在名单里的人 @ 它，**不给任何回应**（不暴露机器人存在） |
| `"allowedUsers": []`（空数组） | **谁都不响应** —— 真正的安全默认值 |
| `"allowAllUsers": true` | **对所有人开放**：这个群里的任何人都能查，白名单不再生效 |

> 想开放给同事，就把 `allowAllUsers` 设成 `true`；想收回，删掉这一行、把 userid 填进 `allowedUsers`。
> 想知道现在到底是开着还是关着，跑一次 `run-fastlane.cmd --check`：它会直接打印**访问策略**那一行。
>
> ⚠️ 历史坑：早期版本把"空数组"实现成了**放行所有人**，与文档正好相反 ——
> 想锁死的人反而门户大开。现已改正：空数组＝谁都不响应，开放必须显式写 `allowAllUsers: true`。

### 9.3 哪些群能用 + 群名

```json
"allowedChats": ["群ID-1", "群ID-2"],
"groups": {
  "群ID-1": { "name": "品牌A数据播报", "brands": ["品牌A"] },
  "群ID-2": { "name": "品牌B数据播报", "brands": ["品牌B"] }
},
```

`groups` 里写群名，好处是日志里能直接看到群名、帮助文案里也会显示"本群："，一眼确认没串群。

### 9.4 加一条新命令

在 `commands` 数组里加一段（照抄一条现有的来改最省事）：

```json
{
  "id": "my-shop-status",
  "label": "门店营业情况",
  "match": ["门店", "营业"],
  "chats": ["群ID-1"],
  "cwd": "D:\\我的脚本\\shops",
  "exe": "D:\\我的脚本\\runtime\\python\\python.exe",
  "args": ["-X", "utf8", "daily_run.py", "--dry"],
  "extract": "separator",
  "timeoutMs": 300000,
  "long": true
}
```

各字段什么意思：

| 字段 | 含义 | 注意 |
|---|---|---|
| `id` | 内部编号 | 英文，随便起，别重复 |
| `label` | 群回复里显示的名字 | 中文 |
| `match` | **全名**触发词，任何群都能用 | 例如 `品牌A门店` |
| `generic` | **通用**触发词，只在"本群唯一指向它"时生效 | 例如两个群都写 `门店` → 在品牌B群就是品牌B，品牌A群就是品牌A；单聊里会反问你哪个品牌 |
| `chats` | 只在这些群可用；留空数组=所有群可用 | 单聊不受这个限制 |
| `cwd` | 脚本所在目录 | **Windows 路径要写双反斜杠** `\\` |
| `exe` | 用哪个 Python | 写完整路径最稳 |
| `args` | 命令参数 | 数组，一项一个；`-X utf8` 能避免中文乱码 |
| `extract` | 从输出里取哪一段 | `separator` = 取两条 `====` 分隔线之间（推荐） |
| `timeoutMs` | 最多跑多久（毫秒） | 慢脚本给 300000（5 分钟） |
| `long` | 只是标记"这条比较慢" | 帮助文案里会提示"较慢，几十秒" |
| `brandScope` | 填 `"group"` 时，**发送前按本群品牌裁剪正文** | 给"一次查多个品牌"的命令用（典型是余额）。不填＝原样发送。单聊没有群身份，永远不裁剪 |

> **改完必须重启程序才生效**（见第 14.3 节）。

## 11. 第六步：自检（不联网，先确认配置没错）

双击 `run-fastlane.cmd` **不行** —— 直接双击会启动常驻程序。自检要在命令行里加参数。

1. 打开程序目录，在地址栏输入 `cmd` 回车（这样打开的窗口就在这个目录里）。
2. 依次运行下面三条：

```cmd
run-fastlane.cmd --check
```
看输出：`SDK: OK`、`secret: 已就绪`、`群绑定` 两行、`命令数: N 条可用`。
若显示 `secret 缺失`，回到第 10 步。

```cmd
run-fastlane.cmd --routes
```
它会打印**每个群里每条触发词会走哪条命令**，例如：

```
=== 品牌B数据播报  &lt;群ID&gt; ===
  门店  -> brandb-shops（品牌B门店营业情况）
  订单  -> brandb-orders（品牌B订单异常）
  品牌A门店 -> （无此命令 → 回帮助）
```

**挨个看一遍**：品牌B群不该出现品牌A的命令，反之亦然。这一步就是"分群不串味"的验收。

```cmd
run-fastlane.cmd --selftest
```
它会**真的把每条命令跑一遍**（几秒到几十秒），但**不会往群里发任何东西**。
看两件事：`exit=0`，以及正文长得像话（有标题、有数据）。
如果提示 `正文里仍有疑似标签`，说明你的脚本用了 `<font>` 之类标签，回到第 8 步让 agent 去掉。

## 12. 第七步：启动并让它常驻

### 12.1 先手动启动一次，确认能连上

在同一个命令行窗口里运行：

```cmd
run-fastlane.cmd
```

看到这样的输出就说明连上了（**这个窗口先别关**）：

```
[2026-09-19 12:39:45] 正在连接企微智能机器人…
[2026-09-19 12:39:45] 已连接企微智能机器人（WebSocket 长连接认证成功）
```

如果报错：
- `缺少机器人凭据` → botId 或 secret 没填对（回第 9.1 / 第 10 步）
- `SDK 错误：... auth ...` → secret 错了，或者复制时带了空格/换行
- 什么反应都没有 → 检查 `logs\fastlane.log`

确认没问题后，在黑窗口里按 `Ctrl + C` 停掉它，进入下一步做成常驻。

### 12.2 注册计划任务（每分钟自动体检 + 掉线自动拉起）

**新建一个记事本，粘贴下面这一行**（如果程序目录不是 `D:\我的程序\wecom-fastlane`，把路径改成你自己的）：

```
schtasks /create /tn WecomFastlane /tr "wscript.exe //nologo D:\我的程序\wecom-fastlane\watchdog-hidden.vbs" /sc minute /mo 1 /f /rl LIMITED
```

保存为 `install-task.bat`（**保存类型选"所有文件"**，文件名要带 `.bat`），
然后**右键 → 以管理员身份运行**。看到 `成功` 字样即可。

> **为什么用 `wscript.exe` 而不是 `powershell.exe`**：powershell 是控制台程序，计划任务每分钟拉起它时，
> 屏幕上会**闪一下黑窗口**（`-WindowStyle Hidden` 挡不住创建瞬间）。`wscript` 是图形界面程序，
> 根本不会创建控制台窗口 —— 这样常驻就完全无感了。

### 12.3 立刻启动一次并确认

```cmd
schtasks /run /tn WecomFastlane
```

等 15 秒，然后检查：

```cmd
type logs\heartbeat.txt
```

应该看到类似 `2026-09-19T04:39:45.577Z pid=12345 authenticated` 的内容（**时间要接近现在**）。
`pid=` 后面那个数字就是程序进程号（下面会用到）。

## 13. 第八步：在群里验收

在群里发（注意 `@` 到正确的机器人）：

```
@数据查询 帮助
```

应该立刻收到一条帮助，上面写着**本群名字**和**本群能用的命令**。

然后试一条真查询：

```
@数据查询 余额
```

**正常表现有两种，都算正常**：

- **配了采集缓存的命令**（多数）：几乎**立刻**出结果，正文第一行是 `> 数据时间：10:03（5 分钟前）`；
- **没配缓存的命令**：1~2 秒内出现"已收到「推广账户余额」查询，正在取数…"，再过十几二十秒，

> 如果超过 1 分钟没有任何反应，直接跳到第 15 节故障排查。

## 14. 日常维护

### 14.1 看一眼它健康不健康

```cmd
type logs\heartbeat.txt
```
- 时间在 **4 分钟以内** → 健康
- 时间很旧、甚至文件不存在 → 连接掉了（看门狗最多 1 分钟内会自己重启；连续两次还不行就看第 15 节）

```cmd
type logs\watchdog.log
```
- **健康时它什么都不写**（安静就是好事）
- 出现 `restarting: ...` 就是在自动救活，属正常自愈

```cmd
schtasks /query /tn WecomFastlane
```
看 `状态`（应为"就绪"或"正在运行"）和 `上次运行结果`（应为 `0`）。

### 14.2 看谁问过什么

```cmd
type logs\fastlane.log
```

每一行都有时间、群（带群名）、谁、发了什么、命中哪条命令、花了多久、输出多大。排查问题时先看它。

### 14.3 加一条新命令 / 改了配置之后

1. 改 `commands.json`
2. 跑 `run-fastlane.cmd --routes` 确认路由对
3. 跑 `run-fastlane.cmd --selftest 你的触发词` 确认脚本能出文本
4. **重启程序**让它生效：

```cmd
schtasks /delete /tn WecomFastlane /f
schtasks /create /tn WecomFastlane /tr "wscript.exe //nologo D:\我的程序\wecom-fastlane\watchdog-hidden.vbs" /sc minute /mo 1 /f /rl LIMITED
```

然后按 **14.1** 确认心跳恢复。想更省事：找到 `logs\fastlane.pid` 里的进程号，结束它，
看门狗会在 1 分钟内自动用新配置拉起来。

### 14.4 备份

把这个文件夹整个复制一份（含 `commands.json` 和 `secret.txt`）。
`logs\` 可以不备份。建议改完配置就备份一次，出问题能立刻回退。

### 14.5 改推送文案

文案在**各个数据脚本**里（不是在这个通道里）。让 agent 改脚本即可，但记住一条：

> **智能机器人的 markdown 不支持 `<font color="...">` 颜色标签**（企微群机器人 webhook 支持，两者不一样）。
> 通道会自动把这类标签剥成纯文本，所以你不会看到裸标签，但**颜色也不会生效**。
> 想要强调就用 `**加粗**` 或 `⚠️` 这类符号。

### 14.6 怎么保证品牌A群里不会出现品牌B的数字

命令表里的 `chats` 只能决定"**这条命令在这个群能不能用**"，决定不了"**同一段输出里哪些行该发出去**"。

余额就是一个例子：它一次查四个账号（两个品牌各两个渠道），输出里天然带着两个品牌。
如果在品牌A群里原样发出去，品牌B的余额就串味了。

解决办法是给这条命令加一个开关：

```json
"brandScope": "group"
```

它的行为：

- 正文按**空行**切成区块；
- 区块里出现哪个"已知品牌"（＝所有群绑定品牌的并集），就归属哪个品牌；
- **只要沾到本群品牌就保留，只沾别的品牌就整块丢掉**；
- 一个品牌都没出现的区块（标题、说明行）一律保留；
- **单聊不裁剪** —— 保持"四个账号一起看"。

改完怎么验证（**不会发群**）：

```cmd
run-fastlane.cmd --selftest 余额 --as-group <品牌A群的群ID>
```

输出里应该**只剩品牌A**，并且日志会写明丢掉了几个他品牌区块。
再跑一次不带 `--as-group` 的，确认单聊视角四个账号都还在。

> 判断标准：**"这个群里的人，本来就有权看到这些数字吗？"**
> 拿不准就别加 `brandScope`，或者干脆把这条命令的 `chats` 限定到该品牌群。

### 14.7 回复里的「数据时间」是什么意思

这套东西默认**不再每次去平台现抓**，而是由程序在后台定期把数据取回来存着，你问的时候直接读那份结果。
好处是**毫秒返回**，而且**平台挂了 / 登录态过期时，仍然答得出上一次成功的数据**。

所以你会在回复的正文第一行看到：

```
> 数据时间：10:03（5 分钟前）
```

- 这一行说的是**这份数据是什么时候取到的**，不是"现在几点"。后台默认每 10 分钟取一次，
  所以看到"几分钟前"是正常的。
- 如果超过 30 分钟没有新数据，程序会再补一行 `> ⚠️ 数据已 45 分钟未更新，仅供参考` ——
  说明取数那边出问题了，但**这份旧数据仍然能用**（这正是它的设计用意，不是故障）。
- 群里发「**状态**」，可以看到**每个数据源**的数据时间 —— 一眼就能看出哪个源卡住了。
- 如果某个源一直很旧、甚至收到「采集器数据陈旧」的主动提醒，按第 15 节处理；
  改了脚本文案之后想让某条立刻生效，就跑 `run-fastlane.cmd --collect <源名>` 手动采一次。

> 想给一条命令也接上这个能力：在 `commands.json` 里给它加 `"snapshot": "<源名>"`（让 agent 帮你加），
> 详细原理见技能里的 `references/11-采集与缓存.md`。

## 15. 故障排查手册

**排查第一步永远是这三条命令**：

```cmd
type logs\fastlane.log
type logs\heartbeat.txt
type logs\watchdog.log
```

| 症状 | 可能原因 | 怎么处理 |
|---|---|---|
| 群里 @ 了完全没反应 | 机器人没加进群 | 群设置里添加这个机器人 |
| 同上 | 你的 userid 不在白名单 | 看 `fastlane.log` 里 `user=` 的值，填进 `allowedUsers`，重启 |
| **同上（别人 @ 了没反应）** | 当前是"仅白名单"模式，而他不名单里 —— 被**静默忽略**（日志里有一行「发送者不在白名单」） | 跑 `run-fastlane.cmd --check` 看**访问策略**那一行；要开放就给 `commands.json` 加 `"allowAllUsers": true`，重启 |
| 同上 | 这个群不在 `allowedChats` | 把 `chat=` 的值补进去，重启 |
| 同上 | 程序没在跑 | 看 `logs\fastlane.pid` 的进程号还在不在；不在就 `schtasks /run /tn WecomFastlane` |
| 日志里只有"收到消息"没有"开始执行" | 触发词没命中 | 用 `--routes` 看正确写法；确认命令名和 `match` 里的一模一样 |
| 提示"这里能查多个品牌，请写明要哪个" | 单聊里用了通用词（如"门店"） | 说全名，例如 `品牌A门店` |
| 回了一条"命令不在本群…"或帮助 | 该命令没绑这个群 | 在 `commands.json` 的 `chats` 里加上这个群 ID，重启 |
| 回复要等十几二十秒才出来 | 这条命令没配采集缓存，每次都在现场抓 | 给它加 `"snapshot": "<源名>"`（见 14.7），配好后通常毫秒返回 |
| 正文里有「⚠️ 数据已 N 分钟未更新」 | 采集没能取到新数据（登录态过期 / 平台改版 / 脚本路径变了） | 先看 `logs\collect.log` 最后几行；再让 agent 跑 `run-fastlane.cmd --collect <源名>` 复现 |
| 群里收到「采集器数据陈旧」的主动提醒 | 某个数据源超过 30 分钟没成功采集 | 同上；这条只推到运维群，业务群里看不到是正常的 |
| 正文里出现 `<font color="comment">` | 脚本用了 HTML 标签 | 让 agent 改成 markdown 加粗；通道也会自动剥掉 |
| 中文变成乱码/方框 | 解释器没按 UTF-8 输出 | `args` 里加 `-X utf8`，并确认脚本本身以 UTF-8 保存 |
| 屏幕每分钟闪一下黑窗 | 计划任务直接跑了 powershell | 按 12.2 改成 `wscript.exe` 那条 |
| 任务显示结果 `2147946720` | "已有实例在运行"（正常跳动） | 只要心跳新鲜就不用管 |
| 提示"已有实例在运行，本进程退出" | 已经有一个在跑（正常保护） | 不用管；确实要换配置就按 14.3 重启 |
| 查一半被告知"上一条查询还在执行" | 单飞锁在起作用（防止两个抓取任务打架） | 等它出结果再发 |
| 说 `secret 缺失` | `secret.txt` 没放对位置/带 BOM | 用 UTF-8 无 BOM 重存，确认只有一行 |
| 说 `SDK 不能加载` | 没装 Node，或路径不对 | `node -v` 确认；重装 Node 18+ |
| 电脑重启后不工作了 | 计划任务需要登录后才跑 | 重新登录即可（开机不登录不会跑） |
| 提示端口/进程冲突 | 有两个实例 | 只保留计划任务那个；把多余的手动启动窗口关掉 |
| **播报数字好几天一模一样** | 查询日期被写死成了常量 | 让 agent 检查：日期范围必须是**每次运行时动态算**的 |
| **播报里报"登录已失效"，过一会儿又正常** | 网络抖动被误判成凭据过期 | 让 agent 把"凭据失效"和"临时失败"分成两类，后者自动重试 |
| **固定的某个时刻数据变成 0** | 平台令牌换发，那一轮请求必失败 | 让 agent 加重试（2~3 轮 + 递增等待）；这是平台行为，不是你的错 |
| **门店数明显不对（多出很多）** | 用错了账号上下文（拿到了父账号的全量池） | 让 agent 检查取数前是否正确切换了账号 |

### 采集信息给技术支持

出问题时，把这三样发给同事，基本能直接定位：

1. `logs\fastlane.log` 最后 30 行
2. `logs\heartbeat.txt` 的全部内容
3. `run-fastlane.cmd --check` 的输出（**注意：这里面不含 secret**）

## 16. 安全边界（为什么可以放心开放给同事）

| 机制 | 作用 |
|---|---|
| 命令表写死 | 只有你列进 `commands.json` 的那几条能跑；别的词只会得到一条帮助 |
| 只读脚本 | 通道本身没有任何"写数据/执行任意命令"的能力，能力上限 = 你放进去的脚本 |
| 三级访问控制 | 人（`allowedUsers` / `allowAllUsers`）× 群（`allowedChats`）× 命令（`chats`），越界一律拒绝 |
| 发送者白名单 | 不在名单里的人 @ 它，**不给任何回应**，不暴露机器人存在。也可以设 `allowAllUsers: true` 主动对全群开放（那时能力上限仍＝你放进去的那几条只读命令） |
| 凭证不出机器 | secret 只存在本机文件/环境变量，不进入任何对话 |
| 单实例保护 | pid + 心跳双重校验，避免同一机器人挂两条连接造成消息重复 |
| 无模型参与 | 命中靠精确匹配，不存在"被话术绕过去"的可能 |
| 长数字拦截 | 播报正文里出现 8 位以上连续数字，直接拦下不发 |

> 给同事开放时，建议先想清楚一件事：**你放进去的脚本能查到什么，他们就能看到什么。**
> 涉及个人隐私或敏感金额的脚本，别放进命令表。

## 17. 怎么安全地停掉

```cmd
schtasks /delete /tn WecomFastlane /f
```

然后再结束正在跑的进程（进程号从 `logs\fastlane.pid` 里读）：

```cmd
powershell -NoProfile -Command "$p=[int](Get-Content D:\我的程序\wecom-fastlane\logs\fastlane.pid -Raw); Stop-Process -Id $p -Force"
```

停掉后：
- 群里 @ 它不会再有任何回复
- **不影响**其他任何定时任务（那些播报脚本照常跑）
- 想恢复：重新执行 12.2 那一行计划任务命令，或直接双击 `start-hidden.vbs`

## 附录 D：脚本开发常见坑（现象 → 根因 → 修法）

这几条都是**真实踩过的坑**，共同点是：**它们都不会报错，只会安静地给你一个错答案**。
所以它们比"脚本崩了"危险得多 —— 崩溃你立刻知道，算错你要几天后才发现。

| 现象 | 根因 | 修法 |
|---|---|---|
| 播报数字连续好几天一模一样 | 查询日期被写死成了常量（比如写成了某一天的全天） | 改成**每次运行时动态计算**日期范围。自检口诀：连续两次数字完全一致，先怀疑日期范围或缓存 |
| 取消原因永远是"已取消" | 取错了字段，代码回退到了笼统的状态描述 | 去响应里找**明细字段**（退款/取消详情里的原因），而不是顶层的状态文案 |
| 门店数突然多出十几倍 | 取数时用了旧的账号上下文，拿到了父账号的全量池 | 确认取数前**已经切换到目标账号**，用切换后的会话去查 |
| 报"登录已失效"，十分钟后重跑又正常 | 网络抖动/页面没准备好，被误判成凭据过期；而且全链路没有重试 | 把错误分成**确定性**（真的过期，要人重新登录）和**临时性**（自动重试）两类；确定性判断要挑一个**不被签名网关拦的接口**去问 |
| 每天固定时刻数据变成 0 | 平台在那一刻**换发令牌**，这一轮请求必失败 | 加 2~3 轮重试 + 递增等待；这是平台行为，重试就能自愈 |
| 脚本报错信息是 `err: None`，查不出原因 | 异常只带了消息文本，而失败时它是空的 | 让异常把**状态码、错误码、完整响应**都打出来 |
| 计划任务里跑失败，手工双击却正常 | 权限/会话环境不同（典型：权限过高导致浏览器启动降权失败） | 让 agent 记录**每次尝试的参数和结果**到日志，逐个变体试；别赌单一组合 |
| 双击 `.bat` 一闪而过、什么都没发生 | `.bat` 里混了中文，或换行不是 CRLF，cmd 解析错位 | `.bat` 保持**纯 ASCII + CRLF**，中文提示全部挪进 Python 脚本（`.ps1` 相反，必须 UTF-8 **带 BOM**） |
| 计划任务某天开始静默停摆，错误码 `2147942402` | 脚本或 Python 换了盘符/目录，而任务里存的是**绝对路径** | 改路径并**重新注册任务**（任务里存的是绝对路径，改文件没用） |

> **一条通用经验**：任何"无人值守"的脚本，都要能回答这个问题 ——
> **"它今天到底跑没跑？"** 做法很简单：每次运行都往一个心跳文件写一行时间戳，
> 事后一眼就能看出是"没跑"还是"跑了但结果是 0"。
